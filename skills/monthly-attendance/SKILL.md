# 月度考勤自动统计

每月需要统计考勤数据并填写Excel考勤表。此skill自动完成以下工作：
1. （可选）从Notion获取IT值班日期
2. 从海航OA系统查询当月公文并截图保存
3. 从公文请示内容中解析休假日期和类型
4. 将所有信息填入Excel考勤模板

## 配置文件

所有个人信息存储在配置文件 `.env` 中（位于本skill目录下：`~/.agents/skills/monthly-attendance/.env`）。

**执行前必须先读取 `.env` 文件**，加载以下配置项：

| 变量名 | 必填 | 说明 |
|--------|------|------|
| `EMPLOYEE_ID` | ✅ | 人事编号 |
| `EMPLOYEE_NAME` | ✅ | 姓名 |
| `DEPARTMENT` | ✅ | 部门名称 |
| `OA_ACCOUNT` | ✅ | OA系统账号（用于Excel行定位） |
| `NOTION_DUTY_PAGE_URL` | ❌ | Notion值班页面URL（留空则跳过值班流程） |
| `NOTION_DUTY_DATASOURCE_ID` | ❌ | Notion值班数据源ID（留空则跳过值班流程） |

首次使用时，参考 `.env.example` 创建 `.env` 文件。如果 `.env` 不存在或缺少必填项，提示用户补充后再继续。

## 输入要求

用户需要提供：
- **月份**：需要处理的年月（如 2026年3月）
- **工作文件夹**：该文件夹下应包含一个 `.xlsx` 文件作为考勤模板，公文截图也将保存到此文件夹

## 执行流程

### Step 0: 加载配置

读取 `~/.agents/skills/monthly-attendance/.env` 文件，解析所有配置项。后续步骤中用 `${EMPLOYEE_NAME}`、`${EMPLOYEE_ID}` 等变量指代配置值。

检查必填项是否齐全，缺失则停止并提示用户。

扫描用户提供的工作文件夹，查找其中的 `.xlsx` 文件作为考勤模板。如果文件夹中有多个 `.xlsx` 文件，提示用户确认使用哪一个；如果没有 `.xlsx` 文件，停止并提示用户。将找到的文件路径记为 `${EXCEL_FILE}`。

判断是否启用值班流程：如果 `NOTION_DUTY_PAGE_URL` 和 `NOTION_DUTY_DATASOURCE_ID` 均非空，则启用；否则跳过 Step 1，IT值班天数视为 0。

### Step 1: 获取IT值班日期（可选 - 仅在配置了Notion值班页面时执行）

**如果未配置 `NOTION_DUTY_PAGE_URL`，跳过此步骤，IT值班日期列表为空。**

从Notion页面 `${NOTION_DUTY_PAGE_URL}` 获取Tasks。

1. 先fetch该页面获取Tasks数据库信息
2. 查询Tasks数据库（`collection://${NOTION_DUTY_DATASOURCE_ID}`）中关联到此项目的所有任务
3. 过滤出目标月份的任务（根据`date:Due:start`判断）
4. 提取Due日期作为IT值班日期列表

每个task的Due日期可能是单日或日期范围。如果是范围（有start和end），则该范围内的所有日期都算值班日。

**重要**：IT值班通常在周末/节假日，值班日期可能是一天或连续两天。

### Step 2: 查询OA公文并截图

使用opencli查询全年公文（因为跨月提交的情况很常见）：

```bash
opencli hnaoa query --year <年份> --category "我呈报的公文" --limit 50 -f json
```

返回结果是全年的公文列表。接下来对每条公文查看详情并解析请示内容，从中提取实际休假日期，最终只保留目标月份的休假记录。

**重要**：公文的 `submit_time`（提交时间）不等于休假日期。比如2月26日提交的公文可能申请的是3月的休假。所以必须解析请示内容中的实际日期来判断。

只对包含目标月份休假日期的公文执行截图保存操作。

对于每一条公文：

1. **查看详情** - 获取请示内容：
```bash
opencli hnaoa view <part_id> --year <年份> -f json
```

2. **截图保存** - 将公文保存为PNG：
```bash
opencli hnaoa save <part_id> --output <文件夹>/公文_<编号>_<标题>.png --year <年份>
```

### Step 3: 解析休假信息

从每篇公文的 `request_content`（请示内容）中提取休假日期和类型。

请示内容有多种写法，以下是真实案例：

**案例1** - 半天休假：
```
申请3月12日下午和3月13日上午休假，使用2026年度年休假1天。
```
→ 3/12下午 年休假(0.5天), 3/13上午 年休假(0.5天)

**案例2** - 全天休假：
```
申请3月11日（星期三）休假，使用2025年度延期年休假1天。
```
→ 3/11 年休假(1天)

**案例3** - 不同措辞：
```
本人申请2026年3月5日请休年假1天
```
→ 3/5 年休假(1天)

**案例4** - 调休/倒休：
```
申请2月27日（星期五）休假1天，使用1月倒休8小时。
```
→ 2/27 调休(1天)

解析规则：
- 查找日期模式：`X月X日`，可能带有`上午`/`下午`/`全天`后缀
- 识别休假类型关键词：

| 关键词 | 休假类型 |
|-------|---------|
| 年休假/年假/延期年休假 | 年休假 |
| 调休/补休/倒休 | 调休 |
| 事假 | 事假 |
| 病假/短病假 | 短病假 |
| 长病假 | 长病假 |
| 中病假 | 中病假 |
| 婚假 | 婚假 |
| 产假 | 产假 |
| 丧假 | 丧假 |
| 育儿假 | 育儿假 |
| 陪护假 | 陪护假 |
| 探亲假 | 探亲假 |
| 带薪休假 | 带薪休假 |
| 无薪休假 | 无薪休假 |
| 产前检查陪护假 | 产前检查陪护假 |
| 男员工护理假 | 男员工护理假 |
| 公司生育奖励假 | 公司生育奖励假 |
| 居家隔离 | 居家隔离 |

- 半天休假计为0.5天
- 注意连续日期范围，如"3月12日至3月14日"
- "使用XX年度年休假X天"这种句式可以辅助确认类型

最终得到一个休假列表，每条包含：
```
{date: "3月12日", period: "下午", type: "年休假", days: 0.5}
```

### Step 4: 填写Excel考勤表

使用xlsx skill（openpyxl）编辑 `${EXCEL_FILE}`。

操作目标是 **"异常情况明细"** 这个sheet（第二个sheet）。

#### 4.1 定位目标行

不要写死列号。不同月份模板里"姓名 / 账号 / 部门 / 职务 / 规则"等列可能会平移。

先检查 **前 3 行的所有列**，动态识别表头，再决定目标行。匹配表头前，对实际表头和下面的预期表头使用相同规则：去除首尾空白和单元格内换行，并使用 NFKC 统一全角/半角字符：

1. 扫描 Row 1~3 的全部非空单元格
2. 识别表头关键词并建立列映射：
   - `姓名` → name 列
   - `账号` → account 列
   - `部门` → department 列
   - `职务` → title 列
   - `所属规则` / `规则` → rule 列
   - `人事编号` → employee_id 列
   - `备注` → remarks 列
   - `工作地点（准确填写，关乎能不能发免餐）` → work_location 列
   - `对应自营食堂名称（准确填写，关乎能不能发免餐）` → canteen_name 列
3. 如果发现一组连续列同时命中 `姓名/账号/部门/职务/所属规则`，优先把它视为"考勤系统导出人员信息区"
4. 如果只发现单独的 `姓名` / `人事编号`，则把它们视为人工补充区

拿到列映射后，按下面顺序定位目标员工行：
1. 先在动态识别出的 `name` 列里匹配包含 `${EMPLOYEE_NAME}` 的值
2. 如果有 `account` 列，再匹配账号 `${OA_ACCOUNT}`
3. 如果有 `employee_id` 列，再匹配 `${EMPLOYEE_ID}`
4. 仍未命中时，才在人工补充区的姓名列里匹配 `${EMPLOYEE_NAME}`
5. 全部找不到，才在已有数据最后一行的下一行新建

**重要**：
- 一旦命中目标员工行，所有已识别的数据列（包括 work_location、canteen_name）和日期列都必须写回这一行
- 不要因为某个补充区姓名列为空，就回退写到别人的行
- 如果匹配到多个候选行，优先选择同时满足"姓名命中 + 账号命中"或"姓名命中 + 规则列包含 IT值班/业务-信息技术部-IT值班"的那一行；若仍冲突，停止并提示人工确认

#### 4.2 高亮目标行

定位到目标员工行后，将该行所有已使用的单元格（A列到最后一个日期列）的背景色设为**黄色**（`PatternFill(start_color='FFFF00', end_color='FFFF00', fill_type='solid')`），使其在整张表中更醒目、便于人工复核。

#### 4.3 理解列结构

关键列对应关系（基于Row 2和Row 3的表头）：
- A列 → 序号
- B列 → 部门（填 `${DEPARTMENT}`）
- C列 → 人事编号（填 `${EMPLOYEE_ID}`）
- D列 → 姓名（填 `${EMPLOYEE_NAME}`）
- E列 → 人员类型（填"行政班"）
- F列 → 是否取消福利（填"否"）
- G列 → 应出勤天数①（本月工作日天数）
- H列 → 休假天数②（所有休假的总天数 - 类型为"调休"的总天数）
- I列 → 实际出勤天数（= ① - ②）
- J列 → 行政班免餐发放天数（保留模板公式；当前更新版为 `= ① - ② - ④ - ⑥ - ⑦ - ⑧ + ⑨`）
- W列 → 调休⑧（类型为"调休"的总天数）
- X列 → 节假日加班、值班（公司坐班）⑨（IT值班总天数；未配置值班则填0）
- AA列 → 备注
- 表头 `工作地点（准确填写，关乎能不能发免餐）` → 填"天津"
- 表头 `对应自营食堂名称（准确填写，关乎能不能发免餐）` → 填"天津航空基地食堂"

上面的字母列是模板参考。2026年7月免餐积分更新版中，两个免餐关联字段分别位于 Q列和R列；仍必须按完整表头动态定位，不要写死列号。如果后续模板发生平移，以实际表头为准。

**重要 - 数值列填零规则**：B列到AA列之间，有些列已包含公式（如I、J、N、P列），**不要覆盖公式**。对于其余没有公式、也没有需要填写的特定值的数值列（如S出差④、T培训⑤、U培训⑥、V学习交流⑦、Y空勤人员上行政班⑩、Z空勤应急备⑪等），应**填入0**而非留空，以确保依赖这些列的公式能正确计算。

具体做法：先读取目标行B~AA范围内每个单元格，判断其当前值是否为公式（以`=`开头的字符串）；如果是公式则跳过不动；如果不是公式，且该列不属于需要填写特定值的列（B/C/D/E/F/G/H/W/X/AA/Q/R，以及动态识别出的 work_location、canteen_name 列），则填入`0`。两个免餐关联字段属于文本列，任何情况下都不能被填零逻辑覆盖。

**注意**：O列（上月补发、扣减积分数）也应填入`0`（不在排除列表中），因为公式P列依赖它。

#### 4.4 填写免餐关联字段

这两个字段是必填项，且内容必须精确一致：

- work_location 列填入 `天津`
- canteen_name 列填入 `天津航空基地食堂`

如果任一完整表头没有找到，或同一表头匹配到多个列，停止处理并提示用户，不要保存缺少免餐关联字段的结果。写入后再次读取目标行这两个单元格，确认值与上述文本完全一致，且没有额外空格。

#### 4.5 计算工作日天数

根据目标月份计算中国法定工作日天数。需要考虑：
- 标准周一至周五为工作日
- 法定节假日（如春节、清明、劳动节、端午、中秋、国庆等）为非工作日
- 调休上班日为工作日

可以使用 `chinese_calendar` 库来准确计算，如果没有安装，就按标准周一到周五计算并提醒用户核实。

#### 4.6 填写日期列

2026年7月免餐积分更新版的日期列为AM:BQ，但后续模板仍可能变化，**不要写死日期列范围**。日期列表头格式为 `"日号\n星期几"`（如 `"1\n星期日"`）。

扫描Row 2和Row 3的所有列，按列号合并识别结果，再定位连续的日期表头区域。当前更新版在Row 2和Row 3重复写有同一组日期表头；同一列中的日号和星期一致时，将它们视为一个日期列，不算歧义。只有同一列的两行内容冲突，或出现多组无法判定的日期区域时，才停止并提示人工确认。最后核对日期序列覆盖目标月份的1日至最后一日。

对于每个日期列：
- 如果该日期有休假，填写休假类型（如"年假"、"调休"等），文字加粗并设为红色
  - 半天休假标注为如"年假0.5天"
- 如果该日期是IT值班日（仅在启用值班流程时），填写"IT值班"，文字加粗并设为红色
- 如果既无休假也无值班，保持原样（不清空原有数据）

**重要 - 日期列字体样式**：不要替换整个Font对象，应保留单元格原有的字体族（font family）、字号等属性，仅修改 `bold=True` 和 `color='FF0000'`。做法是先读取当前单元格的 font，复制其属性后仅覆盖 bold 和 color：
```python
old_font = cell.font
cell.font = Font(name=old_font.name, size=old_font.size, bold=True, color='FF0000')
```

#### 4.7 填写备注列

按 `备注` 表头动态定位备注列（旧模板为AA列），格式示例：
```
3/12下午 年休假, 3/13上午 年休假, 3/21-3/22 IT值班
```

包含所有休假明细和IT值班日期（如有）的汇总。

#### 4.8 保存与复核

覆盖原文件 `${EXCEL_FILE}`。保存后重新打开工作簿并复核目标员工行，确认：

1. `工作地点（准确填写，关乎能不能发免餐）` 的值为 `天津`
2. `对应自营食堂名称（准确填写，关乎能不能发免餐）` 的值为 `天津航空基地食堂`

任一复核不通过时，不得报告处理成功，必须指出缺失或不一致的字段。

## 注意事项

1. OA系统需要在Chrome中保持登录状态才能使用opencli hnaoa命令
2. Excel模板的列结构可能随月份变化（每月天数不同，日期列数量不同），务必根据实际表头动态定位
3. 如果公文没有请示内容或无法解析，将该公文标记为待人工处理并告知用户
4. IT值班日通常是周末，在Excel中对应的日期列填"IT值班"（仅在启用值班流程时）
5. 所有金额/天数的计算应使用Excel公式而非硬编码值（如实际出勤天数 = 应出勤天数 - 休假天数）
6. 处理完成后，给出汇总报告：共处理X篇公文，识别出X天休假（具体明细），X天IT值班（如已启用），并确认工作地点为天津、对应自营食堂为天津航空基地食堂
