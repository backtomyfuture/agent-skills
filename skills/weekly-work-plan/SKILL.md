# 周度工作计划填报

为傅强完成飞书 Base「周度工作计划」的周四例行填报。一次运行做两件事：补上一周的完成情况，再把上一周的计划复制成新一周。

固定目标：

- Base：`https://a1qr0odzabr.feishu.cn/base/IWRrbFNSXaF6ORsm7qtcUSARnie`
- Base token：`IWRrbFNSXaF6ORsm7qtcUSARnie`
- 表：`周度工作计划`
- table id：`tblTvWzgpmXCb0VQ`
- 人员：傅强，open_id `ou_538a14647caf5eef00523c50e7d76521`
- 时区：`Asia/Shanghai`
- 身份：`--as user`。不要切到 bot。

「人员」是创建人字段，不是普通人员列。创建新记录时不要写这个字段，创建人会自动变成当前登录用户。写入前先 `lark-cli contact +get-user --as user`，确认当前用户就是傅强。不是傅强就停止，不要写。

这个 Base 还有其他表和其他人的记录。只读写上面这张表里创建人为傅强的行。

## 触发与范围

用户说「填这周计划」「周四填报」「补上周完成情况」「复制下周计划」时，按下面的默认流程跑完。

用户点名某几条、某周、或给出完成情况说明时，只改点名的范围，说明用用户给的原文。没有点名时，处理「上一周」的全部傅强记录，并原样复制成新一周。

默认流程会写入 Base。用户明确说先看、先读、不要改时，停在读取，把上一周和新一周的现状报出来。

## 字段

可写：

- `下周工作计划`：文本，计划正文
- `工作类型`：单选，复制上周原值
- `所属系统`：单选，复制上周原值；上周为空就留空
- `目标进度`：百分比数字，`1` 表示 100%
- `实际进度`：百分比数字，与该行 `目标进度` 相同
- `目标完成情况`：单选，写 `进度正常`
- `项目是否已完结`：单选，写 `否`
- `是否属于部门月度工作`：单选，复制上周的 `是` 或 `否`
- `完成情况说明（选填）`：短文本
- `本周实际人天`：数字。默认不填，用户给出时才写
- `任务拆解`：关联字段。默认不复制

只读，不要写入：`序号`、`人员`、`填报日期`、`所属周`、`所属周（数字）`、`所属周起始日期`、`完成情况更新日期`。`所属周` 由 `填报日期` 的公式算出，新记录的填报日期就是创建当天。

## 执行

1. 确认身份是傅强。
2. 用当前上海日期确定目标周。ISO 周：周一到周日。周四运行时，「上一周」是上一个 ISO 周，「新一周」是本 ISO 周。用户指定日期或周次时，用指定值代替当前日期。
3. 导出傅强的记录：

```bash
lark-cli base +record-list \
  --base-token IWRrbFNSXaF6ORsm7qtcUSARnie \
  --table-id tblTvWzgpmXCb0VQ \
  --filter-json '{"logic":"and","conditions":[["人员","intersects",[{"id":"ou_538a14647caf5eef00523c50e7d76521"}]]]}' \
  --field-id fldFXJ0ijJ --field-id fldvt2nEMz --field-id fld6XfGlcV --field-id fldRPEKjkS \
  --field-id fldHcLkkx4 --field-id fldgOBf17C --field-id fld0p30PU3 \
  --field-id fldABt61wx --field-id fld2dVpaQ0 --field-id fldooGp7W1 \
  --field-id fldEm4K7t2 --field-id fldI0q1wzh --field-id fldELqxQJn --field-id fldcGG2JUp \
  --format ndjson --output /tmp/weekly-work-plan-fuqiang.ndjson \
  --as user
```

4. 在本地按 `所属周` 分组。`所属周` 形如 `2026年38周`。核对导出结果里的人员全部是傅强，再继续。
5. 上一周没有傅强的记录时停止，不要凭空新建。新一周已经有同文计划时，不要再复制那一条。
6. 更新上一周。每条只提交要改的字段。`实际进度` 取该行已有的 `目标进度`。`目标完成情况` 写 `["进度正常"]`，`项目是否已完结` 写 `["否"]`。已有完成情况说明且用户没要求改写时保留原文；为空时写一句短说明。

```bash
lark-cli base +record-batch-update \
  --base-token IWRrbFNSXaF6ORsm7qtcUSARnie \
  --table-id tblTvWzgpmXCb0VQ \
  --json '{"update_records":{"<record_id>":{"实际进度":1,"目标完成情况":["进度正常"],"项目是否已完结":["否"],"完成情况说明（选填）":"<一句说明>"}}}' \
  --as user
```

7. 创建新一周。从上一条复制 `下周工作计划`、`工作类型`、`所属系统`、`目标进度`、`是否属于部门月度工作`。不要复制完成情况、实际进度、人天、任务拆解。单选用数组，例如 `["AI创新"]`。空的单选不要传空数组。

```bash
lark-cli base +record-batch-create \
  --base-token IWRrbFNSXaF6ORsm7qtcUSARnie \
  --table-id tblTvWzgpmXCb0VQ \
  --json '{"create_records":[{"下周工作计划":"<原文>","工作类型":["AI创新"],"目标进度":1,"是否属于部门月度工作":["是"]}]}' \
  --as user
```

同一张表串行写。一批最多 200 条；超过就分批。

8. 用返回的 `record_id` 读回。确认更新行的人员仍是傅强、实际进度等于目标进度、完成情况是进度正常、完结是否。确认新建行的人员是傅强、`所属周` 是目标新周、计划正文与上一周一致、完成字段为空。

## 完成情况说明

用户给了说明就用原文。没给时，按计划写一句过去时短句，不展开成长段。

- 周报类：`完成本周AI周报优化及发送`
- 培训类：沿用最近一条已写的「第N次培训」，本次写「本周开展了第N+1次培训」。找不到上一次次数时，写 `完成本周AI培训及材料准备`，不要编次数。
- 调研、开发类：`继续推进<计划名>`，计划名过长时保留业务对象，去掉「需求调研」这类后缀重复。

同一计划在更早周次里已经写了说明时，不要把旧说明原样再贴一次。

## 停止条件

出现下面任一情况就停，先告诉用户，不要猜测后继续写：

- 当前登录用户不是傅强
- 筛选结果里出现非傅强记录
- 上一周为空
- 同一周有重复计划，无法判断该更新哪条
- `目标进度` 为空，无法让实际进度与它对齐
- `lark-cli` 返回 `missing_scope`。按它输出的 hint 做增量授权，授权完成后再从失败的那一步继续

## 汇报

完成后列出两张表：上一周每条的序号、计划和写入的说明；新一周每条的序号、所属周和计划。点出说明里由你补写的推断，例如培训次数。
